## 3. 40分版（1時間枠に収めるとき）

### 3-1. なぜ要るのか（5分）

Ctrl+Z との違いを1つだけ。**Ctrl+Z はエディタを閉じたら消える。Git は残る。** それだけ言えば足りる。

「バージョン管理」という言葉は使わない。**「セーブポイント」**と言う。ゲームのセーブと同じで、任意の時点に戻れる。

### 3-2. 3つのコマンドだけ（15分・実演）

Windows の PowerShell か、Claude Code のターミナルで。

```
git status     いま何が変わったか見る
git add .      変更を「保存するもの」として選ぶ
git commit -m "何をしたか"   セーブする
```

**実演の順序**（画面共有で古田が先にやり、次に菊池様に同じことをしていただく）:

1. ファイルを1つ書き換える
2. `git status` で「赤く出る」ことを見る
3. `git add .` → もう一度 `git status` で「緑になる」
4. `git commit -m "テスト"` でセーブ
5. `git log --oneline` でセーブ点が増えたことを見る

> **確認**: 菊池様のご自分の画面で1〜5が通ったか。ここが通らないと以降は意味がない

### 3-3. 戻る（15分・実演）

これが本題。

```
git log --oneline        セーブ点の一覧
git diff                 いま何が変わっているか
git restore <ファイル名>  そのファイルの変更を捨てて、最後のセーブに戻す
```

**実演**: わざとファイルを壊す → `git restore` で戻す → 元に戻ったことを見る。

> 話すこと:
> 「Claude Code に何か頼んで、思っていたのと違うものが出てきたとき。
> `git restore` で頼む前に戻せます。**ここだけ覚えて帰っていただければ、今日は成功です**」

### 3-4. まとめ（5分）

紙1枚に4コマンド（status / add / commit / restore）を書いて渡す。**それ以外は今日は触らない。**

## 4. 60分版（余裕があるとき・上の続き）

### 4-1. GitHub に置く（15分）

「自分のPCが壊れたら全部消える」への対処として。

```
git remote add origin <URL>
git push
```

アカウント作成から入ると時間が溶けるので、**前日までにアカウントだけ作っておいていただく**。

### 4-2. Claude Code に任せる（5分）

菊池様は Claude Code を使われているので、実は**コマンドを覚えなくても「コミットして」と言えば済む**。

ただし**それを最初に言わない。** 中で何が起きているか分からないまま任せると、事故ったときに戻せない。3-2 と 3-3 を手でやったあとに「実はこれ、Claude に頼めます」と出す順序にする。
