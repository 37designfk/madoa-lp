## 0. この資料について

### 0-1. 何のための資料か

Windows パソコンに **Claude Code**（クロード・コード）を入れて、実際の業務で使い始めるまでの手順書です。
印刷して手元に置きながら、画面と見比べて進められるように作っています。

### 0-2. 用語の説明（初出のみ）

| 用語 | 意味 |
|---|---|
| **Claude Code** | Anthropic 社の AI（Claude）を、パソコンの中のファイルを直接読み書きさせながら使うための道具。7月に触った Anti-Gravity CLI（`agy`）の Anthropic 版と考えて差し支えありません |
| **CLI**（シーエルアイ） | 黒い画面に文字を打って操作するやり方のこと。マウスでボタンを押すのではなく、キーボードで命令します |
| **PowerShell**（パワーシェル） | Windows に最初から入っている黒い画面のこと。Anti-Gravity を入れたときに使ったあれです |
| **ターミナル** | PowerShell のような黒い画面の総称 |
| **PATH**（パス） | 「このコマンドはどのフォルダにありますか」をパソコンが探すための住所録。ここに登録されていないと「そんなコマンドは知りません」と言われます |
| **CLAUDE.md**（クロード・エムディー） | 自社のルールやノウハウを書いておくメモ帳ファイル。Claude Code が毎回これを読んでから仕事を始めます。**この資料で一番大事なところです** |
| **スラッシュコマンド** | Claude Code の中で `/` から始める命令。`/help` のように打ちます |

### 0-3. 7月13日にやったこととの対応

Anti-Gravity CLI でやったことと、ほぼ同じ流れです。

| 7/13 にやったこと | 今回やること |
|---|---|
| PowerShell を管理者で開く | PowerShell を開く（**今回は管理者権限は不要**） |
| `irm ... install.ps1 \| iex` でインストール | 同じ形のコマンドを1行実行 |
| `agy` が動かない → PowerShell 再起動 | 同じ症状が出たら同じ対処（7-1 参照） |
| Google アカウントで認証 | Claude のアカウントで認証 |
| フォルダの信頼確認（Do you trust...）に Yes | 同じ確認が出ます |
| 上下キー + Enter、Escape で操作 | 同じ操作系です |

**違うのは1点だけです。** Claude Code は有料プラン（月額）の契約が必須で、無料プランでは使えません。

## 1. 事前に用意するもの

### 1-1. 必要なもの一覧

| 項目 | 条件 | 備考 |
|---|---|---|
| OS | Windows 10 バージョン1809 以降 / Windows 11 | 今のパソコンならまず問題ありません |
| メモリ | 4GB 以上 | |
| CPU | x64 または ARM64 | |
| ネット回線 | 常時接続 | |
| ターミナル | PowerShell または CMD | Windows に標準で入っています |
| **Claude の有料プラン** | Pro / Max / Team / Enterprise のいずれか | **無料プランでは Claude Code は使えません**（2章参照） |

### 1-2. Node.js は必要ありません（重要）

Anti-Gravity のときに話に出た **Node.js は、今回のやり方では不要です。**

公式が推奨している「ネイティブインストール」という方法は、必要なものが全部入った1つのファイルを直接置く方式なので、Node.js を先に入れておく必要がありません。

（Node.js を使う `npm` 経由のインストール方法も存在しますが、その場合は Node.js 22 以降が必要になります。今回は使いません。）

### 1-3. Git for Windows は「あった方がいい」程度

**なくてもインストールできますし、動きます。** 入れておくと、Claude Code がファイル操作をするときの選択肢が1つ増えるという程度のものです。

- 入っていない場合 → Claude Code は PowerShell を使ってコマンドを実行します
- 入っている場合 → Claude Code は Git Bash も使えるようになります

もし入れる場合は https://git-scm.com/downloads/win からダウンロードし、インストーラーの画面はすべて「次へ」で進めて構いません。「Adjusting your PATH environment」の画面では、最初から選ばれている推奨の選択肢のままにしてください。

**当日の判断**: すでに入っているかどうかは当日 `git --version` で確認します。入っていなければ、まず入れずに進めて問題ありません。

### 1-4. 管理者権限は必要ありません

公式ドキュメントに「You do not need to run as Administrator（管理者として実行する必要はありません）」と明記されています。
Anti-Gravity のときは管理者で開きましたが、**今回は普通に開いて構いません。**

## 2. 有料プランを契約する

### 2-1. どのプランが必要か

Claude Code を使うには、以下のいずれかが必要です。

- **Claude Pro**（個人向け・標準）
- **Claude Max**（個人向け・たくさん使う人向け）
- Claude Team / Enterprise（法人向け・複数人で使う場合）
- Claude Console（API 従量課金。使った分だけ請求される方式）

**無料プランには Claude Code は含まれません。**

### 2-2. 菊池様の場合の推奨

まずは **Pro** で始めることを推奨します。理由は次の通りです。

- 従量課金（Console）は、使いすぎたときに請求額が読めません。月額固定のほうが最初は安心です
- 足りなくなったら Max に上げる、という順番で問題ありません
- 「思ったより早く上限に当たる」と感じたら、そのときに 5-3 の使い方の工夫か、Max への変更を検討します

### 2-3. 契約する場所

1. ブラウザで **https://claude.com/pricing** を開く
2. プランを選んで契約する（支払いはクレジットカード）
3. 契約に使ったメールアドレスとパスワードを控えておく（4章のログインで使います）

**注意**: 契約は Web ブラウザ上で行います。Claude Code の黒い画面からは契約できません。

### 2-4. 使用量の考え方

Claude Code には使用量の上限があります。公式の説明では、上限は次の2つの枠で管理されています。

- **5時間ごとの枠**（一定時間使うとリセットされる）
- **週ごとの枠**

上限に当たると「You've hit your session limit」「You've hit your weekly limit」といったメッセージが出て、いつリセットされるかが表示されます。

**具体的な回数・トークン数はプランと時期によって変わるため、当日 https://claude.com/pricing の最新表記で確認します。**（この資料では断定しません）

自分の使用量は、Claude Code の中で `/usage` と打つと確認できます。7/13 に Anti-Gravity で `stats` を見たのと同じ位置づけです。

## 3. インストール

### 3-1. PowerShell を開く

1. キーボードの **Win キー + X** を同時に押す
2. 出てきたメニューから **Windows PowerShell**（または **ターミナル**）を選ぶ

**確認ポイント**: 黒い（または青い）画面が開き、次のような文字とカーソルの点滅が見えていれば成功です。

```
PS C:\Users\ユーザー名>
```

### 3-2. PowerShell か CMD かを見分ける

Windows には見た目のよく似た画面が2つあります。**打つコマンドが違うので、必ず見分けてください。**

| どちらか | 行の先頭の表示 |
|---|---|
| **PowerShell**（こちらを使います） | `PS C:\Users\ユーザー名>` ← 頭に **PS** が付く |
| CMD | `C:\Users\ユーザー名>` ← **PS** が付かない |

**PS が付いていなければ、いったん閉じて 3-1 からやり直してください。**

### 3-3. インストールコマンドを実行する

以下の1行を PowerShell に貼り付けて、Enter を押します。
貼り付けは **Ctrl + V**、または画面上で右クリックです。

```powershell
irm https://claude.ai/install.ps1 | iex
```

読み方: `irm` がインターネットからファイルを取ってくる命令、`iex` がそれを実行する命令です。Anti-Gravity のときに打ったコマンドと同じ形です。

所要時間は 1〜2分程度です。文字がスクロールしていきます。

**確認ポイント**: 完了すると次のメッセージが出ます。

```
Claude Code successfully installed!
```

エラーが出た場合は 7章「よくあるトラブル」を見てください。

### 3-4. 入ったことを確認する

```powershell
claude --version
```

**確認ポイント**: 次のようにバージョン番号と `(Claude Code)` が表示されれば成功です。

```
2.1.211 (Claude Code)
```

数字の部分は日々更新されるので、この通りでなくて構いません。`(Claude Code)` が出ていれば正解です。

`'claude' は、内部コマンドまたは外部コマンド...として認識されていません` と出た場合は **7-1** を見てください。7/13 に `agy` で起きたのと同じ症状です。

### 3-5. より詳しく状態を見たいとき

```powershell
claude doctor
```

インストールの健康診断です。設定ファイルの不備や PATH の問題を、Claude Code 自身が調べて教えてくれます。トラブル時はまずこれを打ってください。

## 4. 初回起動とログイン

### 4-1. 先に作業フォルダを作る

Claude Code は「起動したフォルダ」を作業場所として認識します。7/13 に `mkdir test` → `cd test` → `agy` とやったのと同じ考え方です。

デスクトップに練習用のフォルダを作ります。

```powershell
mkdir $env:USERPROFILE\Desktop\claude-test
cd $env:USERPROFILE\Desktop\claude-test
```

**確認ポイント**: 行の先頭が `PS C:\Users\ユーザー名\Desktop\claude-test>` に変わっていれば、そのフォルダに移動できています。デスクトップにも `claude-test` フォルダができています。

参考: よく使うコマンド

| コマンド | 意味 |
|---|---|
| `mkdir フォルダ名` | フォルダを作る |
| `cd フォルダ名` | そのフォルダに移動する |
| `cd ..` | 1つ上のフォルダに戻る |
| `dir` | 今いるフォルダの中身を一覧表示 |

### 4-2. 起動する

```powershell
claude
```

### 4-3. ログインする

初回起動時は、画面の指示に従ってログインします。

1. 画面にログインを促す表示が出る
2. **ブラウザが自動的に開く**
3. 2章で契約した Claude のアカウントでサインインする
4. 画面の指示に従って許可する
5. PowerShell の画面に戻る

**確認ポイント**: 一度ログインすれば認証情報は保存されるので、次回以降は不要です。

後からアカウントを切り替えたい場合は、Claude Code の中で `/login` と打ちます。

### 4-4. フォルダの信頼確認

初めてそのフォルダで起動すると、「このフォルダの中身を信頼しますか」という確認が出ます。
7/13 に Anti-Gravity で出た `Do you trust the contents of this project?` と同じものです。

自分で作ったフォルダなので **Yes** を選んでください。上下キーで選んで Enter です。

### 4-5. 起動画面の見方

**確認ポイント**: ログインが済むと、Claude Code のプロンプト（入力待ちの状態）が表示されます。その上に次の3つが出ています。

- バージョン番号
- 今使っているモデル名
- **今いるフォルダのパス** ← ここが 4-1 で作ったフォルダになっているか確認してください

ここまで来たらセットアップは完了です。日本語でそのまま話しかけられます。

## 5. 最初に覚える操作

### 5-1. 基本操作

7/13 に練習した CLI の操作感と同じです。

| やりたいこと | 操作 |
|---|---|
| 送信する | 文章を打って **Enter** |
| 動いている Claude を止める | **Esc** |
| 選択肢を選ぶ | **上下キー** で移動して **Enter** |
| 前に打った内容を呼び出す | **↑キー** |
| 使えるコマンドを一覧で見る | **/** を打つ（一覧が出ます） |
| コマンド名を補完する | **Tab** キー |
| 終了する | `exit` と打つ、または **Ctrl + D を2回** |

**マウスでクリックはできません。** キーボードだけで操作します。

### 5-2. まず覚える6つのスラッシュコマンド

| コマンド | 何をするか | いつ使うか |
|---|---|---|
| `/help` | 使えるコマンドの一覧を出す | 迷ったとき |
| `/init` | このフォルダ用の CLAUDE.md を自動で作る | 新しい業務フォルダを作った直後 |
| `/clear` | 会話をリセットして新しく始める | **別の仕事に移るとき（重要）** |
| `/memory` | CLAUDE.md を開いて編集する | 自社ルールを追記したいとき |
| `/usage` | 使用量を確認する | 「上限が心配」なとき |
| `/model` | 使う AI モデルを切り替える | 難しい仕事のとき・節約したいとき |

**`/clear` が一番効きます。** 前の話が残ったままだと、毎回その分の文字数を送り続けることになり、使用量を無駄に食います。「見積もりの話が終わった、次はチラシの話」というタイミングで `/clear` を打つ癖をつけてください。

### 5-3. 許可の求め方と3つのモード

ファイルを変更したり、コマンドを実行したりする前に、Claude Code は許可を求めてきます。

**Shift + Tab** を押すたびに、この厳しさが切り替わります。

| モード | 動き | いつ使うか |
|---|---|---|
| 標準（default） | 変更のたびに聞いてくる | **最初はこれ。何が起きるか見えます** |
| acceptEdits | ファイルの編集は聞かずに実行する | 慣れて、任せていいと思えたら |
| plan（プランモード） | 何も変更せず、やり方の提案だけする | 大きい作業の前に「どうやる気か」を先に見たいとき |

7/13 に「権限確認は基本3番（今後確認しない）でよい」と説明しましたが、**Claude Code は最初のうち標準モードのまま、1つずつ確認しながら進めることを推奨します。** 慣れてから緩めてください。

### 5-4. モデルの切り替え

`/model` と打つと、使う AI の種類を選べます。

- 難しい判断・長い文章の設計 → 上位モデル（消費が大きい）
- 普段の作業 → 標準モデル

迷ったら初期設定のままで構いません。上限が気になり始めたら `/model` で見直します。

## 6. 最初の1時間で成果を出す初期設定

**ここが本番です。** インストールしただけでは、ブラウザで Claude を使うのとあまり変わりません。差が出るのは次の設定からです。

### 6-1. 考え方: プロンプトではなくコンテキスト

7/25 にお話しした通りです。

> 「プロンプトの工夫はもう関係ない。自社のノウハウ、見積もりのルール、お客様への伝え方といった前提条件を AI に食わせることが重要」

ブラウザのチャットは、毎回ゼロから説明し直す必要があります。
Claude Code は、その前提条件を **CLAUDE.md というファイルに書いて置いておける**。これが決定的な違いです。

### 6-2. 業務フォルダを作る

練習用ではなく、実際の業務用のフォルダを作ります。

```powershell
mkdir $env:USERPROFILE\Desktop\sanki
cd $env:USERPROFILE\Desktop\sanki
claude
```

以後、この仕事をするときは必ずこのフォルダで `claude` を起動します。

### 6-3. `/init` で CLAUDE.md の土台を作る

Claude Code を起動した状態で、次を打ちます。

```
/init
```

Claude がフォルダの中身を見て、CLAUDE.md というファイルの下書きを作ります。
（すでに CLAUDE.md がある場合は、上書きせずに改善案を出してくれます）

**確認ポイント**: 実行後、フォルダの中に `CLAUDE.md` というファイルができています。エクスプローラーで確認できます。

空のフォルダで実行すると中身の薄いファイルができますが、それで構いません。**中身は次の 6-4 で人間が書きます。**

### 6-4. CLAUDE.md に自社のことを書く

`/memory` と打つと編集画面が開きます。あるいは、Claude 自身に「CLAUDE.md にこれを追記して」と日本語で頼んでも構いません。

以下は三喜様向けの書き出しの例です。**当日、菊池様の実際のルールに置き換えながら一緒に作ります。**

```markdown
# 株式会社三喜（MADOA）

## 会社について
- 神戸市北区の窓とドアの専門店。創業50年以上
- 個人宅と法人（事務所・クリニック・飲食店・工場）の両方を扱う
- 対応エリアは神戸市および近隣

## 扱う工事と価格の目安
- 内窓リフォーム: 34,000円 / 52,000円 / 76,000円
- カバー工法: 41,000円 / 66,000円 / 88,000円 / 116,000円
- ガラスの割れ替え: 13万円が目安。割れ物のため保証はなし。
  ただし施工後の故障はアフターフォローで対応する
- 調査は無料。出張費無料とは言わない（「調査無料」が正しい表記）
- 調査工事は即日対応できない。「最短」であって断定はしない

## 補助金
- 内窓・カバー工法は補助金の対象になる工事がある
- 法人向けは省エネ補助金が使える案件がある
- 賃貸物件の場合、工事はオーナーとの契約が必要になる

## お客様への文章を書くときのルール
- 断定しすぎない。「最短」「目安」といった言葉を残す
- できないことは正直に書く
- （ここに菊池様の言い回しのルールを追記していく）

## この AI への指示
- 金額や日付は勝手に作らない。分からなければ聞き返すこと
- 出力は日本語。長い説明より箇条書きを優先する
```

### 6-5. 書き方のコツ

公式ドキュメントの推奨に沿ったポイントです。

| コツ | 良くない例 | 良い例 |
|---|---|---|
| **具体的に書く** | 「丁寧に対応する」 | 「調査無料と書く。出張費無料とは書かない」 |
| **200行以内に収める** | 全部詰め込む | 長くなったら別ファイルに分ける |
| **矛盾を残さない** | あちこちに違うルール | 見直して古い記述を消す |

**追記のタイミング**: 「同じ指摘を2回した」と思ったら、それは CLAUDE.md に書くべきことです。3回目からは言わなくて済むようになります。

### 6-6. 置き場所の使い分け

CLAUDE.md は置く場所で効く範囲が変わります。

| 置き場所 | 効く範囲 | 何を書くか |
|---|---|---|
| `C:\Users\ユーザー名\.claude\CLAUDE.md` | **すべての作業** | 「返事は日本語で」「箇条書きで」など、菊池様個人の好み |
| 作業フォルダの直下（`.\CLAUDE.md`） | **そのフォルダの作業だけ** | 会社のルール、価格、工事の知識 |

まずは作業フォルダ直下の1個だけで十分です。

### 6-7. 自動メモ機能について

Claude Code には、指摘したことを Claude 自身が自動で覚えていく機能（auto memory）が初期状態で有効になっています。
画面に「Saved 2 memories」「Recalled 2 memories」と出ることがありますが、正常な動作です。

何を覚えたかは `/memory` から確認・削除できます。

## 7. よくあるトラブル

### 7-1. `'claude' は認識されていません` / `'claude' is not recognized`

**原因**: PATH（住所録）にインストール先が登録されていない。7/13 に `agy` で起きたのと同じ症状です。

**対処1（まずこれ）**: PowerShell の窓をいったん閉じて、開き直してから `claude --version` を試す。7/13 はこれで直りました。

**対処2（それでもダメなとき）**: PowerShell で次の2行を実行します。

```powershell
$currentPath = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$currentPath;$env:USERPROFILE\.local\bin", 'User')
```

実行後、**PowerShell を閉じて新しく開き直してから** `claude` を試してください。

**確認ポイント**: Claude Code のウェルカム画面が出れば成功です。

### 7-2. `'irm' is not recognized`

**原因**: PowerShell ではなく CMD にいます。

**対処**: 窓を閉じて、Win + X → Windows PowerShell を選び直す（3-1 参照）。
どうしても CMD で進めたい場合のコマンドは次の通りです。

```batch
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

### 7-3. `The token '&&' is not a valid statement separator`

**原因**: 逆パターンです。PowerShell にいるのに CMD 用のコマンドを打っています。

**対処**: 3-3 の `irm ...` のコマンドを使ってください。

### 7-4. SSL/TLS のエラー

`Could not create SSL/TLS secure channel` と出た場合。古い Windows 10 で起きます。

**対処**: 次の2行を続けて実行します。

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
irm https://claude.ai/install.ps1 | iex
```

### 7-5. `Claude Code on Windows requires either Git for Windows (for bash) or PowerShell`

**原因**: Claude Code が使えるシェル（コマンドを実行する仕組み）を見つけられていません。

**対処**:
1. `powershell.exe` が標準の場所（`C:\Windows\System32\WindowsPowerShell\v1.0\`）にあるか確認する
2. もしくは Git for Windows を入れる（1-3 参照）
3. Git は入っているのに見つけられていない場合は、場所を教えてやります

```powershell
$env:CLAUDE_CODE_GIT_BASH_PATH="C:\Program Files\Git\bin\bash.exe"
```

Git がどこに入っているか分からない場合は、次で調べられます。

```powershell
Get-Command git | Select-Object Source
```

### 7-6. インストール中に HTML のような文字が出る / 403 エラー

**対処**: まず同じコマンドをもう一度実行してみてください。繰り返し出る場合は、公式のトラブルシューティング（https://code.claude.com/docs/en/troubleshoot-install ）に沿って対処します。当日、古田が同席して見ます。

### 7-7. 文字化け・日本語入力（IME）について

**公式ドキュメントには、Windows での日本語表示・日本語入力に関する記載が見当たりませんでした。** そのため、この資料では対処法を断定しません。

**当日の環境で実際に確認する項目**として扱います。

- 日本語を打って送信できるか
- 変換中の文字が正しく表示されるか
- 出力の日本語が化けないか

もし表示が崩れる場合、標準の PowerShell ではなく **Windows Terminal**（Win + X のメニューで「ターミナル」と表示されるもの）を使うと改善することがあります。ただしこれは公式に記載された対処ではないため、当日その場で試して判断します。

### 7-8. 使用量の上限に当たった

出るメッセージは3種類あり、意味が違います。

| メッセージ | 意味 | 対処 |
|---|---|---|
| `You've hit your session limit · resets 3:45pm` | 5時間ごとの枠を使い切った | 表示された時刻まで待つ。**モデルを変えても回復しません** |
| `You've hit your weekly limit · resets Mon 12:00am` | 週の枠を使い切った | 表示された時刻まで待つ。**モデルを変えても回復しません** |
| `You've hit your Opus limit · resets 3:45pm` | 上位モデル（Opus）の枠だけ使い切った | **`/model` で別のモデルに変えればそのまま作業を続けられます** |

- いずれもメッセージにリセット時刻が表示されます
- 自分の枠と残量は `/usage` で確認できます
- 日常的に当たるようなら、`/clear` をこまめに打つ習慣と、上位プランへの変更を検討します

### 7-9. とにかく困ったとき

**まず打つコマンド**:

```powershell
claude doctor
```

Claude Code 起動中なら `/doctor` でも同じことができます。

**それでも分からないとき**: 7/13 にお見せした通り、**エラーメッセージをそのままコピーして Claude 本人に貼り付けて聞く**のが一番早いです。「分からないことはとにかくこいつに聞く」で構いません。

## 8. 付録: 黒い画面を使わない方法

ターミナルを使わずに、普通のアプリとして Claude Code を使う **デスクトップアプリ版**もあります。

- Windows 用ダウンロード: https://claude.com/download
- 有料プラン（Pro / Max / Team / Enterprise）が必要な点は同じです
- アプリ版には Claude Code が同梱されているため、Node.js も CLI も別途入れる必要はありません
- 起動後、上部中央の **Code** タブを開いて使います
- 変更内容が画面上で見比べられ、承認ボタンで反映する形になります
- **Windows でローカルのフォルダを扱う場合は Git のインストールが必要です**（CLI 版とは条件が違うので注意）
- CLAUDE.md や設定は CLI 版と共有されるので、両方を並行して使えます

**古田の推奨**: 慣れるまではアプリ版のほうが取っつきやすい面がありますが、**7/13 に CLI をひと通り触っていただいたので、菊池様は CLI 版で問題ないと考えています。** CLI のほうが自動化に発展させやすく、最終的にやりたいこと（リマインドの自動送信、出欠の自動集計）に直結します。

当日、時間があればアプリ版もお見せします。
