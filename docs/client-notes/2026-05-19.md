## 反省点・学び

- 出来事: メタ広告 CLI の長期トークン化処理で、最初に 1Password の「Meta App」アイテム（App ID 1456929105806968）を参照して `OAuthException: The access token does not belong to application` エラーが発生。打ち合わせ中の作業フローを2分ほど止めた
- 原因: 1Password の「Meta App」アイテムは過去のもので、古田の Meta Developer アカウントには該当 App ID のアプリが存在しなかった。実際の現行アプリは「Social Analytics Meta App」（App ID 801353823031136）に格納されていた
- 影響: 菊池さんとの打ち合わせ中に「あれ、エラー出てる」と一瞬間が空いたが、その場で原因特定・別アイテム参照に切り替えて復旧。クライアントへの本質的な影響なし
- 教訓: クライアント別の Meta CLI セットアップ時、`~/update-meta-token.sh` がハードコードで参照している `op://Claude Code/Meta App/...` を信用せず、事前にどのアプリで短期トークンを取得すべきかを確認する手順を入れる。または `update-meta-token.sh` を汎用化して App アイテム名を引数で渡せるようにする
- カテゴリ: tooling
- 重要度: medium

- 出来事: 打ち合わせ前に短期トークン → 長期化のフロー全体をリハーサルしていなかったため、菊池さんの前で初回試行＋エラー＋復旧の様子を見せてしまった
- 原因: クライアント別 CLI ラッパー作成は kiraresu 以来で、フローを記憶頼りでやろうとした
- 影響: 古田の準備不足が一瞬伝わる可能性。ただし古田が「Claude Code 実演」として整理して見せたためマイナス影響は最小化された
- 教訓: 新規クライアントのメタ広告セットアップ時は、事前に別ターミナルで「ダミーで一度通す」リハーサルを15分入れる。または `client-add` スキルにメタ広告セットアップの標準フローを組み込んで自動化
- カテゴリ: communication
- 重要度: low
